## 一、背景（测试开发场景）

5.3 的校验器已经"失败会自动重试"，今天解决另一个工程问题：**数据大到装不进内存**。接口回归的日志一行一行流进来，要把 ERROR 和 WARN 挑出来生成报告。用本课三件套：手写迭代器（P0 冒烟用例筛选器）+ 三层生成器管道（读→滤→加工）+ 生成器表达式。**这就是周练习『日志分析脚本』的骨架**——本题做完，周练习等于拼装过一遍。

## 二、文件与流程规格

**定义顺序**：两个数据源 → P0Iterator 类 → 三个生成器函数 → 主流程。本题**零 import**——三件套全是语言内置能力。

### 1. 两个数据源（逐字符照抄进 lesson4.py）

```python
CASES = [("TC001", "P0"), ("TC002", "P2"), ("TC003", "P0"), ("TC004", "P1"), ("TC005", "P0")]

RAW_LOG = [
    "2026-10-18 20:00:01 INFO /login 200 35ms",
    "2026-10-18 20:00:02 ERROR /pay 500 1200ms timeout",
    "2026-10-18 20:00:03 INFO /query 200 42ms",
    "2026-10-18 20:00:04 WARN /cart 200 850ms slow",
    "2026-10-18 20:00:05 ERROR /pay 500 1300ms timeout",
    "2026-10-18 20:00:06 ERROR /order 502 90ms bad-gateway",
    "2026-10-18 20:00:07 INFO /login 200 30ms",
    "2026-10-18 20:00:08 WARN /search 200 990ms slow",
]
```

日志字段按空格切分：`[0]日期 [1]时间 [2]级别 [3]路径 [4]状态码 [5]耗时 [6]详情`。

### 2. P0Iterator 类（你自己写——KP1 主体）

- `__init__(self, cases)`：收 `(case_id, priority)` 元组列表，索引状态自己记
- `__iter__`：返回自身（协议第 1 条）
- `__next__`：吐出下一个 **P0** 用例的 case_id——内部是 **while 循环**：不断前进索引，直到找到 P0（return 它）或确认取完（raise StopIteration，协议第 2 条）
- **内建自查信号**：如果 A 段输出**只有 TC001**，说明你的 __next__ 把「跳过非 P0」写成了「遇到非 P0 就停」——if 写成了没有 while

### 3. 三层生成器管道（你自己写——KP2/KP3 主体）

**① `read_lines(lines)`——数据源层**
- 逐行 yield（真实场景对应 open() 的文件对象，5.1 的 for line in f 同构）

**② `filter_by_levels(lines, levels)`——过滤层**
- 只放行级别字段（`line.split()` 后索引 2）`in levels` 的行，逐行 yield
- **必须用 levels 参数判断，禁止写死 "ERROR"**（导师边界会换 `{"INFO"}` 复验）

**③ `to_report(lines)`——加工层**
- 每行 `parts = line.split()` 后按此格式 yield，**逐字符**：
  `f"{parts[2]} {parts[3]} [{parts[4]}] {' '.join(parts[5:])}"`

### 4. 主流程（逐字符照抄）

```python
if __name__ == "__main__":
    print("=== A 手写迭代器: 只吐 P0 用例 ===")
    p0_iter = P0Iterator(CASES)
    for case_id in p0_iter:
        print(f"  {case_id}")
    print(f"  取完再 list(): {list(p0_iter)}")

    print("=== B 生成器管道: ERROR 与 WARN 流式报告 ===")
    pipeline = to_report(filter_by_levels(read_lines(RAW_LOG), {"ERROR", "WARN"}))
    print("  管道已组装，此时还没加工任何数据")
    report_count = 0
    for report in pipeline:
        report_count += 1
        print(f"  {report_count}. {report}")
    print(f"  共 {report_count} 条")

    print("=== C 生成器表达式: 一次性演示 ===")
    smoke_ids = (f"SMK{i:03d}" for i in range(1, 4))
    print(f"  next 取第 1 个: {next(smoke_ids)}")
    print(f"  list 取剩下的: {list(smoke_ids)}")
```

**C 段内建自查信号**：`list(smoke_ids)` 必须只剩 **2 个**——next 已经吃掉第 1 个，生成器状态共享且一次性。若打出 3 个，说明你中途重建了新的生成器。

### 6. 导师边界验收预告（写代码时心里有数）

import 无副作用（第 10 次实证）／P0Iterator 喂空列表与全非 P0 列表：for 零输出不报错／`iter(p0_iter) is p0_iter`／filter 换 `levels={"INFO"}` 输出即变+空集合 0 条（参数驱动）／to_report 直接喂 list 也能被消费（不挑食）／同一个 pipeline 二次 for：零行（一次性）／`sum(1 for _ in ...)` 计数法不报错（协议兼容）／惯犯 grep 三件套照旧。

## 三、思考题（必交，每题一两句话）

1. **一次性**：A 段 `list(p0_iter)` 是 `[]`，C 段 `list(smoke_ids)` 只剩 2 个——这两个"变少"现象共同的机制是什么？如果业务真的要把 P0 用例**再遍历一遍**，正确姿势是什么（提示：想想 list 为什么能反复 for——它是可迭代对象不是迭代器）？
2. **惰性与拉动**：B 段打印「管道已组装」的那一刻，read_lines 加工了几行？第一条数据是被谁拉动起来的？整条链路里数据是从下层"推"上来的，还是从上层"拉"下来的？
3. **工程取舍**：周练习还要做统计（比如 ERROR 总数、平均耗时）。两种做法：把管道结果先 `list(...)` 落盘再统计 vs 用 for 边消费边计数（像本题 report_count）——各自优缺点是什么？什么情况下可以放心先落 list？（内存与便利的 trade-off——JD"海量日志"场景同构）
