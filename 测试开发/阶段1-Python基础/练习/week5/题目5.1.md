## 一、背景（测试开发场景）

数据驱动测试（Data-Driven Testing）的雏形：用例存在 CSV 文件里，程序逐条读取 → 调接口 → 比对实际响应与预期 → 产出 JSON 测试报告。这是所有接口自动化框架（pytest + requests + allure）的最小骨架。

## 二、文件与流程规格

### 1. cases.csv（你创建，UTF-8，表头 + 5 行数据逐字符照抄）

```
case_id,name,api,expected_status,expected_msg
TC001,登录成功,/login,200,success
TC002,支付成功,/pay,200,success
TC003,查询订单,/order,200,success
TC004,加入购物车,/cart,200,success
TC005,退出登录,/logout,200,success
```

### 2. lesson1.py 里的 fake_api（模拟接口，代替真实 HTTP 请求，逐字符照抄）

```python
def fake_api(api):
    """模拟接口：按路径返回固定响应"""
    responses = {
        "/login": {"status_code": 200, "msg": "success"},
        "/pay": {"status_code": 500, "msg": "server error"},
        "/order": {"status_code": 200, "msg": "success"},
        "/cart": {"status_code": 200, "msg": "success"},
        "/logout": {"status_code": 200, "msg": "success"},
    }
    return responses[api]
```

### 3. 主流程要求

1. 用 `open("cases.csv", newline="", encoding="utf-8")` + `csv.DictReader` 逐条读用例
2. 每条用例调 `fake_api(row["api"])` 拿实际响应
3. 比对两项，**两项都一致才 PASS**，否则 FAIL：
   - 状态码：`int(row["expected_status"]) == resp["status_code"]`
   - 消息：`row["expected_msg"] == resp["msg"]`
4. 每条用例打印一行，格式逐字符：`{case_id} {PASS或FAIL}`（中间一个半角空格，无其他符号）
5. 全部跑完打印汇总行，逐字符：`通过 4/5`——分子分母**必须算出来**，不许写死（导师边界验收会改用例数据重跑）
6. 写 `report.json`：`json.dump(report, f, ensure_ascii=False, indent=2)`，report 结构：
   - 顶层三个键：`total`（int）、`passed`（int）、`results`（list）
   - `results` 每个元素至少含 `case_id`、`status`（值为 "PASS"/"FAIL"）两个键；可自行加字段（如 name / expected / actual）
7. 主流程（读文件、跑用例、打印、写报告）必须放进 `if __name__ == "__main__":` ——导师将 `import lesson1` 验证无副作用 + 跑边界

### 4. 预期运行结果（6 行逐字符）


## 三、思考题（必交，每题一两句话即可）

1. `json.dump` 里去掉 `ensure_ascii=False` 再跑一次，report.json 里出现什么现象？（打开看，实验完还原）
2. 为什么 `expected_status` 必须 `int()` 转换后才能比较——直接 `"200" == 200` 结果是什么、这算假阳性还是假阴性？再想：如果把接口实际返回值也 `int()` 一下，某天接口返回 `200.7`，比对结果会怎样、这种"通过"算什么？（本课程口径：**假阳性 = 看起来过了，其实不该过**）
3. `open` CSV 时 `newline=""` 起什么作用？（提示：Windows 下不写它，csv 读写会多空行）
